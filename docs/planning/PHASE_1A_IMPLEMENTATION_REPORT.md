## 2. Architecture decisions

| Decision | Rationale |
|----------|-----------|
| Config in `frontend/src/shared/config/legal/*` | FE-only Phase 1A; no backend/Firestore changes |
| Field statuses: CONFIRMED / OWNER_INPUT_REQUIRED / LEGAL_REVIEW_REQUIRED / NOT_APPLICABLE / VERIFIED_FROM_CODE | Match owner instructions + code-verified facts |
| Page statuses: DRAFT / PENDING_OWNER_INPUT / PENDING_LEGAL_REVIEW / READY_FOR_OWNER_APPROVAL | Publication gate separate from field fill |
| Prod missing → “Thông tin đang được cập nhật.” | No fabricated values; no raw status enums in UI |
| Dev (`import.meta.env.DEV` or `VITE_LEGAL_DRAFT_UI=true`) → labeled placeholders + status chips | Easy owner/dev discovery |
| Banner when not `READY_FOR_OWNER_APPROVAL` | Page loads ≠ legally approved |
| Shipping fees not copied from `orderFulfillment.ts` into legal text | Owner must confirm official policy text |
| Legal URLs **not** added to sitemap | Avoid SEO “publishing” incomplete policies |
| Footer / auth / DSR / checkout unchanged | Reserved for Phase 1B+ |
